# 学生谈心谈话系统 — 当前领域约束（v9）

## 当前上线范围

核心业务仅包括：教师、学生信息、谈话会话、学生谈话记录、附件、标签、模板。保留个别谈话和集体谈话，管理端以会话为列表根节点，在同一“谈话管理”页面查看参与学生记录。

统一查询和统计分析属于本期上线范围，所有统计与查询必须遵循全校/本学院数据边界。预约、预警、大屏、谈话跟进、学生反馈和“我的记录”仅保留代码与数据，菜单隐藏。`Student-UI` 源码保留但不部署，Nginx 不监听学生端 6090。

## 角色与数据范围

| 角色 | roleKey | 数据范围 | 关键约束 |
|---|---|---|---|
| 内置超级管理员 | `admin` | 全校 | 全部权限 |
| 校管理员 | `school_admin` | 全校 | 与 `admin` 同权限；不能修改、停用或删除内置 admin 账号；可管理其他校管理员 |
| 院管理员 | `college_admin` | 本学院及下级 | 管理本学院全部业务、教师、年级和班级；可升降本学院院管理员，但不可降级自己或最后一名启用院管理员 |
| 老师 | `talk_teacher` | 本学院及下级 | 查看本学院全部业务数据；教师名单只读；学生可增改导入导出但不可删除 |

旧 `talk_secretary`、`talk_counselor` 统一迁移到 `talk_teacher` 并停用。岗位（书记、副书记、辅导员、班主任等）仅作为教师资料展示，绝不决定权限。

教师 Excel 导入的“角色”列只允许老师、院管理员、校管理员，分别对应 `talk_teacher`、`college_admin`、`school_admin`；更新模式按该列替换业务角色，保留无关角色。仅全局管理员可分配或修改校管理员；院管理员只能管理本学院，不能降级自己或最后一名启用院管理员。内置管理员账号禁止通过教师导入修改。

教师、登录账号和角色以每行独立事务提交，单行失败全部回滚并继续下一行。兼容没有“角色”列的旧模板：新账号默认老师，已有管理员角色保留。

角色改变时撤销已有登录会话。请求鉴权还必须从数据库刷新当前账号状态、角色、学院和菜单权限，不能将 Redis 旧角色缓存作为授权真相；这样并发登录或旧请求写回缓存也不能持续保留已撤销权限。此路径增加每次认证请求的用户和角色菜单查询。

教师和院管理员的 `sys_user.dept_id` 必须直接指向 `dept_type=college` 的学院节点；缺失或指向其他层级时，业务查询使用 `collegeDeptId=-1` 失败关闭，不返回数据。

## 业务权限

| 资源 | 老师 | 院管理员 | admin / 校管理员 |
|---|---|---|---|
| 教师资料与账号 | 本学院只读 | 本学院增删改、导入、角色升降 | 全校全部操作 |
| 学生信息 | 本学院查看全部字段、筛选、新增、修改、导入、导出；不可删除 | 本学院全部操作 | 全校全部操作 |
| 年级/班级 | 只使用已有班级 | 本学院增删改 | 全校增删改 |
| 谈话会话/记录/附件 | 本学院全部可见、可导出；仅本人创建的谈话可写/删除 | 本学院全部可写 | 全校全部可写 |
| 学院标签/模板 | 本学院共同维护 | 本学院共同维护 | 全校全部操作 |
| 系统内置标签/模板 | 全校可读可用，不可维护 | 全校可读可用，不可维护 | 可维护 |

学生新增和导入不再创建 `sys_user`。已有学生账号和 `talk_student` 角色保留但停用。删除学生也不删除历史学生账号。

## 数据权限实现

- 业务读写统一通过 `TalkPermissionUtils` 判断精确角色与学院。
- 学生、会话、记录、附件、标签、模板和教师的列表查询在 Service 层注入参数化 `collegeDeptId`；禁止依赖前端菜单作为安全边界。
- 会话创建时从全部参与学生上溯学院，禁止空参与人或跨学院集体谈话，并把学院写入 `talk_session.college_dept_id` 作为历史快照。
- 老师调动学院不迁移历史谈话；其对原学院谈话立即失去访问权。
- 老师对会话、记录和附件的写操作同时校验学院与 `talk_session.create_by`；院管理员和全局管理员按各自范围管理。
- Mapper 只使用 `#{}` 参数化条件。框架 `@DataScope` 仅用于系统部门树等通用模块，不替代谈话业务的显式范围校验。

## 标签、模板与历史

- `talk_tag.scope_type` 使用 `system` / `college`，学院定义通过 `college_dept_id` 归属。
- 模板沿用 `template_type=system/personal`；`personal` 在 v9 中表示“学院模板”，并通过 `college_dept_id` 归属，不再表示个人私有。
- 现有标签和模板迁移为系统内置。
- `talk_session_tag.tag_value` 与会话/记录中的正文是历史快照；修改、停用或逻辑删除定义不反向修改历史。
- 记录及创建反馈的新跟进状态只允许 `none`（无需跟进）、`pending`（待跟进）、`in_progress`（跟进中）、`completed`（已完成）。历史未知状态继续可读；更新未提交状态字段时不重写旧值，不启用隐藏的跟进菜单。

## 删除语义

删除谈话会话为物理级联删除：先尝试删除实际附件文件并记录失败日志，再在事务中删除 `talk_attachment`、`talk_student_record`、`talk_session_tag` 和 `talk_session`。标签和模板定义仍使用逻辑删除，以避免影响可追溯性。

## 组织结构

`sys_dept` 层级为学校 → 学院 → 年级 → 班级，学生挂在班级节点。老师可在本学院已有班级间移动学生；院管理员可维护本学院年级与班级，但不可修改学院节点或跨学院移动组织。
