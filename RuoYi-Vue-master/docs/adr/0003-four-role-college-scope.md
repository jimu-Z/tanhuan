# ADR-0003: 四类角色与学院快照数据边界

## 日期

2026-09-08

## 状态

已采纳

## 背景

旧权限由“书记/辅导员/班主任”等岗位驱动，数据范围分别依赖学院、班级关联和创建人，导致同一业务在多个 Service、Controller 和统计 SQL 中出现不同过滤规则。学生端本期也不再上线，原角色与菜单已不符合当前业务。

## 决策

采用 `admin`、`school_admin`、`college_admin`、`talk_teacher` 四类角色。岗位仅作为资料字段。非全局角色以账号直接所属学院为唯一读范围，并由 Service 层显式注入参数化 `collegeDeptId`。

谈话会话新增 `talk_session.college_dept_id` 历史快照。创建会话时从参与学生推导且要求所有学生同学院；后续教师调动不改变历史归属。老师可读本学院全部谈话，但只能写自己创建的会话及其记录、附件。

标签和模板分为全校系统内置与学院共享定义。系统定义仅全局管理员维护，学院定义由本学院老师和院管理员共同维护，历史会话保留文本快照。

## 结果

- 列表可见性不再因岗位不同而分叉。
- 菜单授权与后端对象级校验形成双层防护。
- 无有效学院的账号失败关闭。
- 旧角色迁移和菜单矩阵集中在 `sql/talk_role_permission_v9.sql`。
- 统一查询与统计分析面向四类有效角色发布，并遵循同一学院数据边界；学生端、预约、预警、大屏、跟进和反馈代码保留但当前不发布。

## 取舍

学院快照带来一个明确的交接成本：教师调院后不会继续访问旧学院谈话，需要全局管理员处理必要的历史交接。这换取了稳定、可审计且不随人员调动漂移的数据归属。
