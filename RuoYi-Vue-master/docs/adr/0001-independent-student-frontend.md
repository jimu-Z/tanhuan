# ADR-0001: 独立学生端前端架构

## 日期

2026-06-01

## 状态

已采纳

## 背景

学生谈心谈话系统需要新增学生端面向，允许学生登录查看谈话记录、在线填写反馈。需要决定学生端前端的技术架构方案。

## 决策

**采用独立 Vue2 + Element UI 前端项目**，而非在现有管理端 (`ruoyi-ui`) 中通过路由+菜单区分角色。

## 考虑的方案

| 方案 | 描述 |
|------|------|
| A. 同一套前端 + 角色路由 | 学生和管理员/辅导员共用 `ruoyi-ui`，通过角色权限控制菜单可见性 |
| B. 独立学生端前端（采纳） | 新建独立前端项目，仅包含学生端页面，独立部署 |
| C. Vue3 + Element Plus + 响应式 | 全新技术栈，适配 PC 端和移动端 |

## 理由

1. **隔离性**：学生端和管理端功能边界清晰，独立项目可避免权限泄漏风险（学生误访问管理页面）
2. **部署灵活性**：学生端可部署在独立域名或子路径，便于未来接入微信、企业微信等渠道
3. **维护成本可控**：复用现有前后端 API 层 (`@/api/talk/`) 和认证机制（Spring Security + JWT），开发效率高
4. **移动端适配**：未来可独立优化学生端移动端体验，不影响管理端
5. 方案 A 中单一代码库角色分支复杂度过高；方案 C 技术升级成本大且与现有后端对接风险高

## 影响

- 新增独立前端项目，需额外配置 Nginx 路由和构建流水线
- 学生端复用管理后端 API，后端需新增学生角色权限配置和对应 API 权限标识
