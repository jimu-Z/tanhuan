# 学生导入多人管理升级说明

部署新后端前，备份数据库并执行 `RuoYi-Vue-master/sql/student_import_managers_v10.sql`，创建学生—管理教师、班级—管理教师、学生账号归属三张表。脚本可重复执行，不更改已有账号密码、角色启停或菜单。首次将旧教师班级名关联按教师学院转换为班级ID关联，保留原管理范围；重跑不扩大已经精确绑定的同名班级范围。

教师列沿用当前导入模板中的辅导员、班主任、书记、副书记列；现在仅表示填写管理人，不再按列名限制教师岗位。可填同学院教师姓名或工号，多人用顿号、逗号、分号分隔。同名教师需要工号消歧，管理人须已有教师资料。管理员若没有教师资料，需先建立对应教师资料，不能仅凭管理员用户名绑定。

一个学生、一个班级均可绑定多位教师或管理员。每次导入只追加缺少的关联，不清空原有管理人。班级关联按班级ID保存，避免同名班级跨年级串联。管理关联不会改变原有学院数据访问权限。

新增学生账号用户名为学号，初始密码123456，保存为BCrypt密文。账号分配学生角色但处于停用状态，学生端暂不开通。重复覆盖不会重置密码或改变启停状态；发现教师、管理员等非本学生账号占用学号时该行失败。学号不超过用户名数据库允许的30字符。

系统已有学生需选“覆盖已有数据”，才能补建学生账号或追加管理关系；“跳过重复学号”保留原状。同一Excel内重复学号仍只处理第一条，应把多名教师写在同一行的教师列中。

每行组织、学生、账号、角色、绑定一并提交或回滚，其他行继续处理。导入结果分别显示成功、跳过、失败和新增账号数。覆盖模式的选填空值仍可能覆盖旧资料，请先备份并核对模板内容。

学生手动新增不在此次自动建号范围内。历史学生资料和绑定不会批量自动补建，需通过覆盖导入处理。

删除通过导入建号的学生，保留账号和可核验归属，后续重导可安全复用，密码不变。手动修改已明确关联学生的学号、姓名、班级时同步其账号，遇用户名占用则整次修改回滚。缺少明确归属的遗留孤立账号需要管理员核对，不能仅凭同名自动接管。

教师页手动取消某人的班级管理时，新旧班级关系一并清理，不影响其他管理人；通过导入单独建立的学生直接管理关系仍保留。
